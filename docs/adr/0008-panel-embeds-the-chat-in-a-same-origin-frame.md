# The Casual panel embeds the chat in a same-origin frame

The Casual tab is a third-column application panel. Nothing in the plugin API renders a transcript, so the only way to show a chat *inside* that panel is to embed one. Casual loads the ordinary chat route in a same-origin iframe (`name="pi-web-casual-embed"`), then trims that frame's chrome: the context bar, navigation panel, workspace column, and mobile tabs are hidden, and unrelated sibling branches above `chat-view` are hidden too. The plugin's own host bridge stays quiet inside the frame so no second ⁂ button or sidebar filter appears there.

## Consequences

- The Casual tab now presents a usable chat surface in place, which is what the panel was asked to be. A project chat in the main column is untouched, so both are visible at once without a second browser window.
- The frame is a full PI WEB client: it opens its own connection to the session daemon and loads the whole bundle a second time. That is the cost of embedding, and why **Open in its own tab** and **Open chat** still exist for lighter paths.
- Trimming depends on host internals (`chat-view`, `prompt-editor`, `status-bar`, and the column element names already used by the shadow-DOM bridge). It is supervised rather than applied once: the frame boots its own SPA, so the first `load` fires before `chat-view` exists. A persistent stylesheet hides the known chrome, a 300 ms pass hides the sibling branches above the chat, and the chat's own ancestors are never hidden.
- The 300 ms pass leaves alone any sibling branch that is showing an open dialog or popover. PI WEB renders its pickers as siblings of the conversation layout, not inside it, so trimming every sibling hid the thinking-level picker, the model picker, the command dialog, the session tree, and the auth sheet within one pass of their opening. A branch hidden before its dialog opened is restored on the next pass, because the dialog is set to top layer while its host stays invisible otherwise.
- The trimmed frame hides the embedded app's own navigation, so a user cannot change project inside it. That is intentional: the frame is a chat, not an app.
- The frame sizes itself to the host's panel content (`height: 100%`, `flex: 1 1 auto`) rather than to a `calc(100vh - Npx)` guess, so the embedded composer lands on the panel's bottom edge instead of floating above dead space.
- Hiding the side panels leaves their grid tracks in place, which squeezed the chat beside an empty navigation column. The injected stylesheet also collapses `.shell` to one `minmax(0, 1fr)` column and lets `main` span it, so the transcript and composer use the frame's full width. Those rules are unlayered, so they outrank the host's layered shell stylesheet.
- The tab carries no toolbar. A chat surface with plugin buttons above and below it was the complaint that produced this ADR, so **New**, **Reset**, **Change home**, **Open**, and **Open in Its Own Tab** moved into the palette, which was already the plugin's control surface. (ADR 0011 later added a conversation strip above the chat: numbered tabs, **+**, and **×**. That is navigation between conversations, not a toolbar, and this rule still holds for commands.)
- The frame's own copy of the app is pinned to the frame's viewport (`position: fixed; inset: 0`) with no safe-area padding, because as a top-level page it would size itself with `100dvh` and pad for the home indicator the page around the frame has already accounted for.
- The remembered pointer is refreshed without navigating (`syncCasualHome`, which replaced `refreshCasualPointer` in [ADR 0012](0012-the-strip-is-shared-through-the-home.md)) so the frame follows the active conversation. A stale pointer would otherwise embed a route the host rejects.
- Inside the frame `window.name` is the marker, the same mechanism the separate window uses for closing. Two window names, two meanings: `pi-web-casual-embed` (quiet plugin) and `pi-web-casual-chat` (standalone).
- If the panel is ever restored as the active tab inside the embedded app, it renders the card instead of nesting another frame.
